# CampusSpace — лабораторная 4

## Запуск

В PowerShell откройте проект `C:\Users\SamirPula\campus_space`:

```powershell
flutter pub get
flutter devices
flutter run -d emulator-5554
```

Подставьте ID из `flutter devices`, если он другой. Эмулятор сначала запускается
через Android Studio → Device Manager. После изменения корня Provider нужен
полный запуск или `R` (hot restart), а не `r`.

Вход: `student@utm.md`, пароль `123456`. Это пример корректного ввода, а не
серверная учётная запись: L4 сохраняет локальную проверку входа из L3.

## Что реализовано

1. provider 6.1.5+1 подключён над роутером L3.
2. RoomModel и BookingModel наследуют ChangeNotifier через CollectionModel.
   Коллекции доступны только для чтения. Фильтры, текст формы, флажки и состояние
   отправки остаются локальными в State.
3. RoomRepository и BookingRepository задают CRUD Future<Result<T>>.
   Mock-реализации используют память, задержку 800 мс и переключаемый отказ.
4. Каталог, детали, избранное, история, форма и статистика показывают загрузку,
   ошибку с повтором или данные. Неизвестный ID после загрузки — не вечный spinner.
5. Избранное, счётчики и статусы синхронизируются между вкладками. Отмена сохраняет
   заявку со статусом «Отменена», удаление убирает её после диалога подтверждения.
6. Форма создаёт заявку через repository; ID выдаёт хранилище. Ошибка не очищает
   поля. Повторный submit во время запроса заблокирован. Пересечения активных
   бронирований одного помещения отклоняются.
7. Профиль содержит «Симулировать сбой сети» и дополнительную задержку 3 секунды
   для удобного снятия loading. Seed-данные импортируют только mock-репозитории.

## Сценарий скриншотов

Нумерация S01–S17 совпадает с местами в отчёте. Делайте кадры приложения, а не
кода. Оставляйте видимой нижнюю панель с бейджами. Скрывайте клавиатуру перед
снимком. Если поля не помещаются, вставьте два кадра под одной подписью.

### S01–S03 — три состояния каталога

После горячего перезапуска войдите. Начальные значения: **8 помещений,
6 избранных, 8 заявок, 3 активных**. Заявки не являются реальным расписанием UTM.

- **S01.** В профиле включите «Задержка 3 секунды для скриншота». В каталоге
  нажмите кнопку обновления сверху. Снимите заголовок «Каталог помещений»,
  круговой индикатор и панель вкладок до появления карточек.
- **S02.** Дождитесь загрузки. Покажите «8 помещений · избранных 6», первые
  карточки, бейдж избранного 6 и бейдж активных заявок 3.
- **S03.** В профиле включите «Симулировать сбой сети». Вернитесь в каталог,
  нажмите обновление. Покажите «Сервер не отвечает — повторите попытку» и
  кнопку «Повторить». Повтор при включённой аварии снова даёт ошибку.

Выключите аварию и задержку в профиле, вернитесь в каталог и нажмите
«Повторить». Данные должны вернуться. Не выключайте реальный интернет:
ошибка имитируется программно и работает независимо от соединения.

### S04–S09 — одна мутация на трёх экранах

Здесь меняем только **Семинарскую 1-118 (r5)**. Изначально её нет в избранном.

- **S04.** В каталоге до изменения: 8 помещений, избранных 6, бейдж 6.
- **S05.** Откройте Семинарскую 1-118, прокрутите вниз. Снимите заголовок,
  кнопку «В избранное» и бейдж 6. Пока не нажимайте кнопку.
- **S06.** Перейдите на вкладку «Избранное»: заголовок «Избранное (6)»;
  r5 ещё не добавлена. При необходимости снимите два кадра списка.
- Вернитесь во вкладку «Каталог»: детали r5 сохранятся. Нажмите «В избранное».
- **S07.** Те же детали: кнопка «Убрать из избранного», заполненное сердце,
  бейдж 7. Дождитесь завершения операции.
- **S08.** Избранное: заголовок «Избранное (7)» и карточка Семинарской 1-118
  (прокрутите до неё). Бейдж 7.
- **S09.** Вернитесь в каталог и закройте детали стрелкой назад. Покажите
  «8 помещений · избранных 7» и бейдж 7. Перезагружать список не нужно.

Проверьте также удаление из избранного свайпом карточки влево: число станет 6.
При включённой аварии неудачный свайп оставляет карточку на месте.

### S10–S14 — форма, изменение статуса и удаление

Сначала сделайте **R**, войдите снова: это гарантирует исходные 8 заявок и ID
новой заявки B-2000. Откройте Аудиторию 3-304 → «Выбрать помещение».

- **S10.** Заполните форму: дата **завтрашнего дня** в формате ДД.ММ.ГГГГ,
  начало **10:00**, окончание **11:00**, участников **12**, цель
  **Подготовка проекта PAM L4**. Снимите заполненные поля без ошибок и кнопку
  «Отправить заявку». Не используйте дату из старого отчёта.
- Отправьте. Форма закроется, заявка появится в расписании r1.
- **S11.** «Мои заявки»: **Всего заявок: 9 · активных: 4**, новая **B-2000**,
  Аудитория 3-304, та же дата и время, цель, статус **Ожидает**.
- **S12.** Откройте B-2000, нажмите «Отменить бронирование», подтвердите
  «Да, отменить». Покажите **Отменена**, ID, дату/время и бейдж активных **3**.
  В истории всё ещё 9 заявок; в активном расписании r1 этой заявки уже нет.
- **S13.** В той же заявке нажмите «Удалить заявку». Снимите диалог с её ID
  и кнопками «Оставить»/«Удалить». Затем подтвердите удаление.
- **S14.** История: **Всего заявок: 8 · активных: 3**, B-2000 больше нет.
  Обновлять экран вручную для этого не требуется.

### S15–S16 — ошибка формы без потери ввода

Сделайте **R**, войдите, откройте r1 и его форму. Введите завтрашнюю дату,
10:00–11:00, 12 участников и цель **Проверка ошибки L4**. Переключитесь
в профиль, включите аварию, затем обратно в каталог: форма и её текст останутся.
Не нажимайте обновление каталога в этом сценарии.

- **S15.** Нажмите «Отправить заявку». Снимите SnackBar с ошибкой и сохранённые
  поля. Экран не закрывается, число заявок остаётся 8, активных 3.
- В профиле выключите аварию. Вернитесь к той же форме и повторите отправку.
- **S16.** История: **9 заявок, 4 активных**, B-2000 с целью
  **Проверка ошибки L4**. Это тот же ввод, не заполненный заново.

## Проверка и защита

```powershell
flutter pub get
dart analyze .
flutter test
flutter build apk --debug
```

Автоматические тесты не заменяют демонстрацию на вашем эмуляторе.
В этой среде `flutter analyze` столкнулся со сбоем процесса LSP; проверка
`dart analyze .` прошла без замечаний. Исходный код использует штатные анализаторы
Flutter/Dart и flutter_lints.

Android APK в среде автоматической проверки собрать не удалось: Gradle сообщил,
что каталог `flutter/packages/flutter_tools/gradle` недоступен для записи.
Поэтому успешная сборка APK не заявляется. Выполните команды выше в обычном
пользовательском терминале; при повторении ошибки сохраните полный вывод
`flutter run -v` для диагностики. Предупреждение Java о native access само по себе
не является причиной этого отказа.

На защите покажите: загрузку → детали → избранное и счётчик → удаление свайпом →
форму → новую заявку → отмену/удаление с диалогом → ошибку и успешный retry.
На L5 меняются реализации RoomRepository/BookingRepository и их создание
в CampusSpaceRoot; демонстрационные переключатели профиля удаляются.
UI и модели не должны знать конкретный источник данных.

Для сдачи замените инструкции S01–S17 своими изображениями в DOCX и снова
экспортируйте PDF как **PAM_L4_MeliuhSamir.pdf**. Приложенный PDF с местами
для скриншотов — версия до вашей финальной вставки. Обычный выход из аккаунта
не очищает mock; полное завершение или hot restart восстанавливает seed.
