# CampusSpace conformance — самостоятельный набор

Этот набор и `../openapi.yaml` созданы самостоятельно по исходникам
полученного учебного Dart-сервера и требованиям L5. Исходный комплект
преподавателя отсутствует. Это не восстановленные оригинальные тесты:
состав наших 37 сценариев определён в этом проекте.

## Запуск

В первом терминале запустить сервер по `../server/SETUP_RU.md`.
Во втором:

```powershell
cd C:\Users\SamirPula\campus_space\conformance
dart pub get
dart run bin/conformance.dart --base-url http://localhost:8080 --json-output results.json
```

Зависимостей кроме Dart SDK нет. Альтернативный прямой запуск:
`dart bin/conformance.dart --base-url http://localhost:8080`.
Код завершения: 0 — все проверки пройдены, 1 — есть ошибки, 64 — неверные аргументы.
Тайм-аут охватывает весь запрос и чтение ответа; недоступный сервер не даёт PASS.
При ошибках выводятся названия сценариев и типы ошибок, но не JWT и не тела ответов.

Использовать локальную учебную базу. Каждый прогон создаёт двух пользователей
с уникальными email, две заметки и один файл. Заметки удаляются проверками;
пользователи и файл остаются (API не предусматривает их удаления).
При прерванном прогоне могут остаться заметки. Чужие записи тесты не удаляют.

## Сценарии

| Номера | Что проверяется |
|---|---|
| 01–04 | Health, CORS, обязательный JWT, неверный токен |
| 05–11 | Регистрация, имя, повторный email, неверный пароль, вход, профиль |
| 12–20 | Пустой список, создание/чтение, ID, страницы, поиск по названию/тексту, обновление |
| 21–24 | Валидация записи, сохранение данных при ошибке, битый JSON, отсутствующая запись |
| 25–28 | Изоляция пользователей и 404 на чужие GET/PUT/DELETE |
| 29–30 | Пустой ответ 204, отсутствие удалённой записи и повторное удаление |
| 31–37 | JWT upload, multipart, метаданные, байты/заголовки download, ошибки и лимит 5 MiB |

Ожидаемые статусы, поля JSON и коды ошибок проверяются явно. Набор не является
автоматическим генератором тестов из OpenAPI и не покрывает все возможные входы.
OpenAPI отдельно проверяется валидатором спецификации.

`openapi-spec-validator` подтвердил корректность OpenAPI 3.0.3: 8 путей,
11 операций. Анализатор Dart для conformance вывел `No issues found`,
но завершился с ненулевым кодом в среде автоматизации; успешный запуск самого
набора проверен отдельно и завершился с кодом 0.

## Результат базового сервера

11.11.2026: **37/37 PASS**, код завершения 0. Машинный отчёт сохранён в
`results-baseline.json`. Он помечен `officialCourseSuite: false`.

Первый прогон дал 36/37: повреждённое multipart-тело вызывало исключение
в callback парсера вне ожидаемого stream error и оставляло запрос незавершённым.
В `server/lib/files.dart` добавлена граница обработки асинхронных ошибок запроса.
Сценарий 36 не ослаблялся; после исправления он получает 400 VALIDATION_ERROR.

После добавления сущностей CampusSpace повторить этот же набор. Он защищает
базовый контракт auth/notes/files; проверки новых сущностей будут отдельными.
Для отчёта корректная формулировка: «Самостоятельно разработанный набор
CampusSpace: 37/37». Не называть его официальным набором преподавателя.
