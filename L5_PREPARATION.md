## Повторная проверка и запуск

Запустить Android-эмулятор через Android Studio → Device Manager, затем:

```powershell
cd C:\Users\SamirPula\campus_space
flutter pub get
dart analyze .
Write-Host "ANALYZE_EXIT=$LASTEXITCODE"
flutter test
Write-Host "TEST_EXIT=$LASTEXITCODE"
flutter devices
flutter run -d emulator-5554
```

Если устройство имеет другой ID, заменить `emulator-5554` значением из
`flutter devices`. При ошибке сохранить полный вывод, не удаляя кэши и
не меняя версии инструментов наугад.

Контрольный сценарий L4: войти с `student@utm.md` / `123456`, увидеть
8 помещений, 6 избранных, 8 заявок и 3 активных. Проверить добавление
в избранное, создание заявки, отмену/удаление и демонстрационный сбой.
Это локальная валидация, а не серверный аккаунт. Подробный сценарий — в L4_GUIDE.md.

## Ограничения для следующих этапов

- Сейчас модели вызывают `load()` при создании корня. При подключении HTTP
  загрузку и очистку данных нужно привязать к авторизованной сессии в корне.
- `byId`, избранное, счётчики и занятые интервалы используют полный список.
  Их адаптация к частичной загрузке относится к отдельному этапу пагинации.
- Тесты L4 используют производственные mock-классы. При удалении mock из
  приложения тестам понадобятся собственные fixtures/fakes.
- В материалах найдены L5 и C01–C07. Комплект `05_Backend` с шаблоном,
  `openapi.yaml` и `conformance` пока не найден. Он нужен для следующего пункта:
  методичка требует расширить шаблон курса и проверить его набором соответствия.
- Код HTTP, сервер, новые зависимости и отчёт L5 на этом этапе не создавались.
